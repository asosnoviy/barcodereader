# barcodereader

HTTP-сервис, который принимает PDF в base64 и возвращает значения QR-кодов и
линейных штрихкодов, найденных в документе.

Реализация целиком на чистом Go: PDFium подключён как WebAssembly-модуль
(runtime Wazero), поэтому cgo и C-компилятор не нужны, а бинарник собирается
одинаково под Windows, Linux и macOS.

## Быстрый старт

```bash
make run                       # запуск на :8080
make test                      # тесты
make test-race                 # тесты с детектором гонок
make gendata                   # пересоздать фикстуры в testdata/
docker build -t barcodereader . # образ без cgo
```

## API

### POST /api/v1/decode

Принимает PDF в base64 внутри JSON:

```bash
curl -s http://localhost:8080/api/v1/decode \
  -H 'Content-Type: application/json' \
  -d "{\"pdf_base64\": \"$(base64 -w0 testdata/qr_embedded_png.pdf)\"}"
```

Либо сырым PDF — так удобнее из шелла:

```bash
curl -s http://localhost:8080/api/v1/decode \
  -H 'Content-Type: application/pdf' \
  --data-binary @testdata/qr_embedded_png.pdf
```

base64 принимается в стандартном и URL-безопасном алфавите, с переводами строк
внутри значения и без padding.

### Поля запроса

| Поле | Тип | По умолчанию | Назначение |
|---|---|---|---|
| `pdf_base64` | string | — | обязательное, документ в base64 |
| `options.pages` | string | все | выборка страниц: `"1"`, `"1-3"`, `"1,3,5-7"` |
| `options.include_barcodes` | bool | `INCLUDE_BARCODES` | искать линейные штрихкоды |
| `options.return_all_qr` | bool | `RETURN_ALL_QR` | искать все QR на странице, а не только первый |
| `options.max_pages` | int | `MAX_PAGES` | сколько страниц сканировать максимум |
| `options.dpi` | int | `RENDER_DPI` | DPI рендера страниц |
| `options.force_render` | bool | `false` | рендерить страницы даже если стадия A что-то нашла |

### Ответ `200 OK`

```json
{
  "request_id": "3f7c1c9e5a1b2c3d",
  "found": true,
  "value": "https://example.com/doc/page-1",
  "codes": [
    {
      "value": "https://example.com/doc/page-1",
      "kind": "qr",
      "format": "QR_CODE",
      "page": 1,
      "source": "embedded_image",
      "image_object": 5,
      "bbox_points": {"x": 56.69, "y": 107.72, "width": 226.77, "height": 226.77},
      "points": [{"x": 157, "y": 299}, {"x": 383, "y": 300}]
    },
    {
      "value": "4601234567893",
      "kind": "barcode",
      "format": "EAN_13",
      "page": 1,
      "source": "rendered_page",
      "bbox_points": {"x": 62.36, "y": 374.79, "width": 194.49, "height": 0}
    }
  ],
  "meta": {
    "pages_total": 3,
    "pages_scanned": 1,
    "dpi": 200,
    "stages_used": ["embedded_image", "rendered_page"],
    "codes_total": 2,
    "codes_unique": 2,
    "duplicates_collapsed": 0,
    "elapsed_ms": 87
  }
}
```

**Про поля:**

- `value` — значение главного кода: QR на самой ранней странице, а если QR в
  документе нет — первый штрихкод.
- `kind` — `qr`, `barcode` или `matrix` (Data Matrix). Нужен, чтобы фильтровать
  единый массив, не разбирая имя формата.
- `source` — `embedded_image` (быстрый путь) или `rendered_page`.
- `image_object` — номер объекта PDF, присутствует только для `embedded_image`.
- `bbox_points` — координаты. Для `rendered_page` это пункты страницы; для
  `embedded_image` — пиксели исходной картинки, потому что положение картинки
  на странице без разбора content stream неизвестно.
- `points` — координаты от ZXing; есть только у кодов из встроенных картинок.
- `codes` — всегда массив, даже если пуст (`[]`, не `null`).

### Свёртка одинаковых значений

Записи с одинаковым `value` сворачиваются в одну. Сортировка идёт до свёртки по
странице и порядку обнаружения, поэтому остаётся вхождение с наименьшим номером
страницы. Сколько записей отброшено — видно в `meta.duplicates_collapsed`.

Следствие: если один и тот же текст закодирован и в QR, и в штрихкоде, в
`codes[]` останется одна запись с форматом первого найденного.

### Ошибки

Тело ответа всегда содержит `found: false` и объект `error`:

```json
{
  "request_id": "3f7c1c9e5a1b2c3d",
  "found": false,
  "error": {"code": "no_codes_found", "message": "QR-коды и штрихкоды в документе не найдены",
            "details": {"pages_scanned": 3, "pages_total": 3}}
}
```

| HTTP | `error.code` | Когда |
|---|---|---|
| 400 | `invalid_json` | тело не является корректным JSON |
| 400 | `missing_field` | нет `pdf_base64` |
| 400 | `invalid_base64` | строка не декодируется |
| 400 | `invalid_pages` | некорректная выборка страниц или `max_pages`/`dpi` ≤ 0 |
| 400 | `not_a_pdf` | нет сигнатуры `%PDF-` |
| 413 | `payload_too_large` | превышен лимит размера |
| 415 | `unsupported_media_type` | Content-Type не `application/json` и не `application/pdf` |
| 422 | `pdf_encrypted` | PDF защищён паролем |
| 422 | `pdf_unreadable` | файл повреждён или не поддерживается |
| 404 | `no_codes_found` | документ валиден, кодов нет |
| 429 | `too_many_requests` | не получен слот декодирования |
| 503 | `no_capacity` / `shutting_down` | перегрузка или останов сервиса |
| 504 | `timeout` | превышен `REQUEST_TIMEOUT` |
| 500 | `internal_error` | непредвиденный сбой |

### Служебные эндпоинты

- `GET /healthz` — liveness, всегда 200, пока процесс жив.
- `GET /readyz` — готовность; 503, если сервис завершает работу.

## Как это работает

Документ проходит две стадии:

1. **Стадия A — встроенные изображения.** Через `pdfcpu` извлекаются растровые
   объекты PDF, и коды ищутся прямо в них. Здесь QR читается за десятки
   миллисекунд и в исходном качестве.
2. **Стадия B — рендер страниц.** Страницы растеризуются через PDFium
   (WebAssembly) в оттенках серого, и коды ищутся в растре. Стадия покрывает
   векторные QR, сканы целиком и штрихкоды, нарисованные линиями.

Стадия B запускается, только если стадия A ничего не нашла — это и есть быстрый
путь. Если в документе одновременно есть встроенная картинка с QR и
нарисованные векторами штрихкоды, ставьте `"force_render": true`.

Поиск кодов внутри одного изображения идёт лестницей попыток: стандартная
адаптивная бинаризация → `TRY_HARDER` → глобальная гистограмма → инверсия
(светлый код на тёмном фоне). Если ничего не найдено, страница перерисовывается
с повышенным DPI.

## Конфигурация

Всё настраивается переменными окружения, файлов конфигурации нет.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `ADDR` | `:8080` | адрес слушания |
| `REQUEST_TIMEOUT` | `30s` | таймаут декодирования |
| `MAX_PDF_BYTES` | `20971520` | лимит размера PDF |
| `MAX_BODY_BYTES` | `31457280` | лимит тела запроса |
| `MAX_PAGES` | `10` | сколько страниц сканировать максимум |
| `MAX_RENDER_PIXELS` | `26000000` | бюджет пикселей на рендер |
| `RENDER_DPI` / `RENDER_DPI_MAX` | `200` / `400` | DPI первой и второй попытки |
| `RETRY_HIGHER_DPI` | `true` | делать ли вторую попытку рендера |
| `MAX_IMAGE_DIM` | `3000` | предел стороны картинки при поиске QR |
| `ONED_MAX_WIDTH` | `1600` | ширина копии для поиска линейных кодов |
| `REGION_SEARCH` | `true` | поиск по тёмным областям после промаха (см. ниже) |
| `REGION_MARGIN` | `8` | поле вокруг найденной области; `0` — четверть стороны символа |
| `ENABLE_EMBEDDED_STAGE` | `true` | стадия A |
| `INCLUDE_BARCODES` | `true` | искать линейные штрихкоды по умолчанию |
| `RETURN_ALL_QR` | `true` | искать все QR на странице |
| `PDFIUM_WORKERS` | `min(4, CPU)` | размер пула PDFium |
| `MAX_CONCURRENT` | `PDFIUM_WORKERS` | сколько документов декодировать одновременно |
| `QUEUE_WAIT` | `2s` | сколько ждать слот; иначе 429 |
| `LOG_LEVEL` | `info` | `debug` \| `info` \| `warn` \| `error` |
| `LOG_PAYLOADS` | `false` | логировать ли сами документы и значения кодов (PII!) |

## Устройство проекта

```
cmd/barcodereader     запуск сервиса: конфиг, пул PDFium, сервер, shutdown
cmd/gendata           генерация PDF-фикстур
internal/config       разбор и валидация окружения
internal/httpapi      HTTP-контракт: разбор запроса, DTO, маппинг ошибок
internal/decode       оркестратор: стадии, лимиты, свёртка дубликатов
internal/pdfembedded  стадия A: извлечение встроенных изображений (pdfcpu)
internal/pdfrender    стадия B: пул PDFium, рендер страниц, подбор DPI
internal/scan         декодирование кодов (gozxing) и препроцессинг
internal/testimages   генераторы изображений для тестов и фикстур
testdata              PDF-фикстуры, зафиксированы в репозитории
```

## Поиск кодов, стоящих не по центру страницы

Детектор Data Matrix в ZXing (`WhiteRectangleDetector`) начинает осмотр **от
центра кадра** и расширяет прямоугольник наружу. Поэтому символ, сдвинутый от
центра, не находится: поиск упирается в край страницы и возвращает `NotFound`.
Ни увеличение кода, ни повторная попытка с `TRY_HARDER` это не исправляют — на
этикетках код почти всегда стоит не по центру.

Поэтому последним рубежом (только если обычный проход по странице ничего не
нашёл) включается поиск по тёмным областям:

1. страница бинаризуется по порогу Оцу, связные тёмные области ищутся обходом
   в глубину на уменьшенной копии;
2. кандидаты фильтруются по размеру и пропорциям;
3. каждый кандидат вырезается с полем тишины и декодируется обычным ридером —
   теперь символ оказался в центре кадра, и штатный детектор работает;
4. координаты результата пересчитываются в систему координат страницы, поэтому
   `bbox_points` и `points` остаются корректными.

Отключается переменной `REGION_SEARCH=false`.

## Замечания по эксплуатации

- **Архитектура.** Собирайте под `amd64` или `arm64`: только на них Wazero
  компилирует wasm-модуль, на остальных платформах он работает в
  интерпретато и заметно медленнее.
- **Старт.** Инициализация пула PDFium занимает около секунды — Wazero
  компилирует модули при старте. Уменьшите `PDFIUM_WORKERS`, если старт критичен.
- **Размер бинарника.** Встроенный wasm-модуль делает бинарник заметно больше
  наивного.
- **Отмена запроса.** Таймаут останавливает пайплайн между страницами и между
  попытками, но не прерывает уже начатый вызов PDFium внутри wasm: одна попытка
  может отработать целиком.
- **Путь Go.** Если `go` не найден в `PATH`, укажите полный путь, например
  `C:\Program Files\Go\bin\go.exe`.
- **`make test-race`.** Детектор гонок требует cgo, а значит C-компилятор.
  На машине без gcc цель не запустится: нужен `CGO_ENABLED=1` и gcc/mingw.
  Обычный `make test` (с `CGO_ENABLED=0`) работает везде.
- **Сеть.** При загрузке модулей прокси `proxy.golang.org` может быть
  недоступен; при обрывах (EOF, таймаут TLS) достаточно повторить загрузку.
  Зеркала вроде `mirrors.aliyun.com/goproxy` использовать не стоит: они
  отдавали модули с несовпадающей контрольной суммой. Проверка сумм
  (sum.golang.org) не отключается никогда.

## Тесты

- `internal/scan`, `internal/config`, `internal/decode`, `internal/httpapi` —
  модульные тесты на стабах.
- `internal/httpapi/integration_test.go` — сквозной путь на настоящих PDF из
